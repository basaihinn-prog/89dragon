  How It Works

  Mobile App Login Flow

  Request:
  POST /api/mobile/login
  {
    "username": "player1",
    "password": "password123",
    "app_version": 1,
    "platform": "android"
  }

  Response if version is outdated:
  HTTP 426 Upgrade Required
  {
    "error": "update_required",
    "message": "Please update your app to the latest version to continue.",
    "update_info": {
      "current_version": 1,
      "latest_version": "2.0.0",
      "version_code": 2,
      "download_url": "https://bxbet.asia/downloads/app-v2.0.0.apk",
      "release_notes": "New version with enhanced features and security improvements",
      "force_update": true
    }
  }

  Response if version is current:
  HTTP 200 OK
  {
    "token": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "app_version": {
      "current_version": 2,
      "latest_version": 2,
      "latest_version_name": "2.0.0",
      "update_available": false,
      "force_update": false
    }
  }

  Managing Versions

  To Release a New Version (e.g., 3.0):

  -- Deactivate all old versions
  UPDATE w_app_versions SET is_active = 0;

  -- Add new version
  INSERT INTO w_app_versions
  (platform, version_code, version_name, download_url, force_update, release_notes, is_active, created_at, updated_at)
  VALUES
  ('android', 3, '3.0.0', 'https://bxbet.asia/downloads/app-v3.0.0.apk',
   1, 'Major update with new features', 1, NOW(), NOW());

  To Allow Optional Update (don't force):

  UPDATE w_app_versions SET force_update = 0 WHERE version_code = 2;

  API Endpoints Summary

  1. POST /api/mobile/login - Checks version during authentication
    - Parameters: username, password, app_version, platform
    - Blocks login if outdated + force_update=true
  2. POST /api/mobile/check-update - Check for updates (no auth)
    - Parameters: version_code, platform
    - Returns update availability info
